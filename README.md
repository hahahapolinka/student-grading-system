# Система учёта студентов и оценок

**Автор:** Гаврилова Полина Валерьевна
**Направление:** учебный проект по стандартной библиотеке C++ (STL)
**Язык / стандарт:** C++17
**Тип приложения:** консольная (CLI) система с интерактивным интерпретатором команд

---

## 1. Назначение и учебная цель

Проект носит учебный характер и выполнен в рамках лабораторного практикума,
посвящённого стандартной библиотеке C++. Его цель — не создание промышленного
продукта, а демонстрация осознанного применения механизмов STL при проектировании
нетривиальной доменной модели: хранилища с несколькими вторичными индексами,
интерактивного интерпретатора команд, текстовой сериализации и аналитических
выборок по группам и датам.

Фокус работы — владение стандартной библиотекой: упорядоченные ассоциативные
контейнеры, разделяемое владение через умные указатели, алгоритмы и итераторы,
потоковый ввод-вывод, таблица диспетчеризации на `std::function`. Подробный
разбор того, какие именно средства STL где задействованы, приведён в разделе 3.3.

Не являются целью и не реализованы (и не заявлены как реализованные):
многопоточность, внешняя СУБД, графический интерфейс, сетевое взаимодействие,
защита от враждебного ввода. Поведение команд рассчитано на корректный ввод
пользователя-преподавателя; некорректные команды отклоняются предсказуемо,
но глубокой валидации строк не предполагается.

## 2. Ключевые возможности

- Интерактивный интерпретатор команд (REPL) с единой таблицей диспетчеризации.
- Хранение студентов с уникальным идентификатором, ФИО и принадлежностью к группе.
- Учёт оценок (шкала 2–5) с привязкой к дате; изменение и удаление оценок.
- Поиск студента по ID и по ФИО с разрешением неоднозначности (одинаковые ФИО
  в разных группах).
- Групповые выборки: список студентов группы, топ-N по среднему баллу,
  список студентов группы риска ниже заданного порога.
- Аналитика по группе: распределение оценок, лучшие и худшие 3 студента,
  сравнение среднего балла группы со средним по остальным группам; агрегация
  за неделю или месяц.
- Средний балл по всем студентам на указанную дату.
- Сериализация всей базы в текстовый файл и загрузка обратно; проверка
  корректности файла без входа в интерактивный режим.
- Пакетный обмен оценками: экспорт шаблона группы для выставления оценок и
  последующая загрузка заполненного шаблона.
- Валидация ввода и единый маркер некорректной команды `INVALID COMMAND`;
  подтверждение деструктивных операций.

## 3. Архитектура

Приложение разделено на уровни: разбор команд, доменное хранилище и доменные
сущности. Каждый уровень отвечает за своё и не смешивает ответственности.

### 3.1 Компоненты

| Компонент | Ответственность |
| :--- | :--- |
| `CommandProcessor` | Интерактивный цикл: чтение строки, разбор имени команды и аргументов, диспетчеризация через таблицу `имя → обработчик`, формирование вывода. Не знает о внутреннем устройстве хранения. |
| `StudentDatabase` | Доменное ядро: хранение студентов и групп, вторичные индексы, бизнес-операции (добавление/удаление/перевод, работа с оценками, выборки, статистика, сериализация). Возвращает результат как значение, не печатая в консоль. |
| `student::Student` | Сущность студента: `id`, `fullName`, `group`, карта `дата → оценка`, кэшированный средний балл. |
| `date::Date` | Сущность даты (`year`, `month`, `day`) с операторами сравнения, ввода и вывода; используется как ключ в картах оценок и индексах. |

### 3.2 Индексы хранилища

`StudentDatabase` поддерживает несколько представлений одних и тех же данных,
чтобы разные типы запросов не сканировали всю базу:

| Индекс | Тип | Назначение |
| :--- | :--- | :--- |
| `students` | `map<StudentID, shared_ptr<Student>>` | Первичный ключ: прямой доступ к студенту по ID за логарифмическое время. |
| `groups` | `map<string, map<StudentID, shared_ptr<Student>>>` | Студенты по группам для групповых выборок, статистики и экспорта/импорта оценок. |
| `nameToStudentIndex` | `map<string, set<StudentID>>` | Обратный индекс ФИО → множество ID; находит всех носителей одного ФИО и корректно обрабатывает неоднозначность в `infostudent` / `listgrades`. |
| `dateToGradesIndex` | `map<Date, vector<pair<StudentID, int>>>` | Индекс «дата → оценки этого дня»; даёт средний балл за дату (`avgmarkbydate`) без обхода всех студентов. |

Все коллекции упорядочены, что обеспечивает логарифмический поиск/вставку/удаление
и естественный упорядоченный обход, необходимый для выборок «топ», «группа риска»
и статистики по диапазону дат.

### 3.3 Использование стандартной библиотеки (STL)

Реализация построена на примитивах стандартной библиотеки; ниже — какие механизмы
где применены и какую задачу они решают. Это ядро учебной цели проекта.

| Средство STL | Где применено | Зачем |
| :--- | :--- | :--- |
| `std::map` (упорядоченный) | `students`, `groups`, `nameToStudentIndex`, `dateToGradesIndex`, `Student::grades_` | Логарифмический доступ/вставка/удаление по ключу и детерминированный упорядоченный обход без ручной поддержки сортировки. |
| `std::set` | значения в `nameToStudentIndex` | Уникальность ID при одном ФИО и эффективное извлечение студента из индекса при удалении. |
| `std::shared_ptr` | хранение сущностей `Student` во всех индексах | Разделяемое владение: один объект виден из `students`, `groups` и индексов одновременно без ручного `new`/`delete`; `shared_ptr<const Student>` отделяет чтение от мутации. |
| `std::vector` + `std::back_inserter` | материализация результатов выборок (топ, риск, список группы) | Плоские упорядоченные результаты для вывода и дальнейшей обработки алгоритмами. |
| `<algorithm>`: `for_each`, `transform`, `partial_sort_copy`, `copy_if`, `any_of`, `remove_if`, `find_if`, `min` | статистика групп, топ-N, риск-студенты, удаление из индексов, разбор файлов | Декларативная обработка вместо ручных циклов; `partial_sort_copy` выбирает топ-N без полной сортировки всей базы. |
| `<numeric>`: `accumulate` | суммы оценок для средних баллов (студент, группа, дата) | Агрегация без явного накопления в цикле. |
| Потоковые итераторы `std::istream_iterator` / `std::ostream_iterator` | загрузка базы и построчная обработка файла оценок | Чтение записей и строк через итераторный протокол STL, без ручного управления позициями в файле. |
| `std::function<void()>` + `std::map<string, …>` | `CommandProcessor::commandMap_` | Таблица диспетчеризации команд: добавление новой команды — одна запись, без ветвления в цикле. |
| `std::pair<bool, T>` | возвращаемые значения операций БД | Статус успеха вместе с результатом без исключений для «ожидаемых» провалов (не найден, дубликат, нет доступа к файлу). |
| Перегруженные `operator>>` / `operator<<` | `date::Date`, `student::Student` | Интеграция доменных типов с iostream-машинерией STL: сущности читаются и пишутся так же, как встроенные типы. |

## 4. Режимы запуска

Программа запускается из консоли. Аргументы при старте задают начальный режим:

| Запуск | Поведение |
| :--- | :--- |
| `students` | Старт с пустой базой, переход в интерактивный режим. |
| `students <file>` | Загрузка базы из `<file>` при старте, затем интерактивный режим. |
| `students --help` | Вывод справки по командам и форматам. |
| `students --check <file>` | Проверка корректности описания базы в `<file>` без входа в интерактивный режим. |

После старта программа читает команды из stdin в интерактивном цикле.
Завершение работы — штатной командой выхода (актуальный список команд и
синтаксис доступны через `--help`).

## 5. Интерактивные команды

Обозначения: `<ID>` — числовой идентификатор студента; `<ФИО>` — полное имя;
`<Группа>` — имя группы; `<Оценка>` — целое из множества {2, 3, 4, 5};
`<Дата>` — дата в формате, принимаемом программой (см. `--help`);
`<Файл>` — путь к текстовому файлу.

### 5.1 Работа с базой

| Команда | Описание | Ошибка → `INVALID COMMAND` |
| :--- | :--- | :--- |
| `loadbase <Файл>` | Загрузить базу из файла. | файл не читается / некорректен |
| `save <Файл>` | Сохранить текущее состояние базы в файл. | файл не записывается |
| `clear` | Полностью очистить базу. | требует подтверждения `y/n`; без `y` действие отменяется |

### 5.2 Студенты

| Команда | Описание | Ошибка → `INVALID COMMAND` |
| :--- | :--- | :--- |
| `addstudent <ФИО> <Группа>` | Добавить студента; ID присваивается автоматически. | студент с таким ФИО уже есть в этой группе; группа не существует |
| `deletestudent <ID>` | Удалить студента и все его оценки. | студент не найден |
| `infostudent <ID>\|<ФИО>` | Вывести ФИО, группу и средний балл. При вводе ФИО и нескольких совпадениях — показать список ID и запросить выбор. | студент не найден; выбран несуществующий ID |
| `listgroup <Группа>` | Список студентов группы в виде `ФИО – {оценки} – средний балл`. | группа не найдена |
| `listgrades <ID>\|<ФИО>` | Список оценок студента в виде `<Дата>: <Оценка>`. | студент не найден |
| `movegroup <ID> <Новая_Группа>` | Перевести студента в другую группу. | студент не найден; целевая группа не существует |

### 5.3 Оценки

| Команда | Описание | Ошибка → `INVALID COMMAND` |
| :--- | :--- | :--- |
| `addgrade <ID>\|<ФИО> <Оценка> <Дата>` | Поставить оценку на дату. Если оценка на эту дату уже есть — сообщить, что нужно использовать `changegrade`. | некорректная оценка/дата; студент не найден |
| `changegrade <ID>\|<ФИО> <Новая_Оценка> <Дата>` | Изменить оценку на указанную дату. | оценка на дату отсутствует; некорректные значения; студент не найден |
| `removegrade <ID>\|<ФИО> <Дата>` | Удалить все оценки студента на указанную дату. | студент не найден; неверный формат даты |
| `avgmarkbydate <Дата>` | Средний балл по всем студентам за дату. | нет оценок на дату / неверный формат |

### 5.4 Выборки и аналитика

| Команда | Описание | Ошибка → `INVALID COMMAND` |
| :--- | :--- | :--- |
| `topstudents <N>` | Топ-N студентов по среднему баллу; если N больше числа студентов — вывести всех. | некорректный N |
| `riskstudents <Порог>` | Студенты со средним баллом ниже порога. Порог в диапазоне (0, 5]. | порог вне диапазона |
| `groupstats <Группа> [--by <week\|month>]` | Аналитика группы: распределение оценок, лучшие и худшие 3 студента, сравнение со средним по остальным группам. Необязательный флаг ограничивает период неделей или месяцем. | группа не найдена; некорректный флаг |

### 5.5 Пакетный обмен оценками

| Команда | Описание | Ошибка → `INVALID COMMAND` |
| :--- | :--- | :--- |
| `exportforgrades <Группа> <Файл>` | Экспортировать шаблон файла для выставления оценок группе (строки `ID`, `ФИО`, пустое поле `Оценка`). | группа не найдена; файл не записывается |
| `loadgrades <Группа> <Дата> <Файл>` | Загрузить оценки группы на дату из заполненного шаблона. Некорректные строки пропускаются. | группа не найдена; файл не читается |

> Реализация процессора дополнительно содержит обработчики групповых выборок
> «топ» и «группа риска» в пределах одной группы, а также явного создания группы.
> Их точный синтаксис приводится в справке `--help`.

## 6. Форматы файлов

### 6.1 Файл базы данных

Файл базы — внутренний текстовый формат, который программа сама читает
(`loadbase` / запуск с аргументом-файлом) и сама пишет (`save`). Он предназначен
для round-trip хранения и не рассчитан на ручное редактирование: структура
записей, порядок полей и представление дат задаются реализацией операторов
потокового ввода/вывода сущности `Student`. Для проверки корректности такого
файла без загрузки служит `--check <file>`.

### 6.2 Шаблон для выставления оценок

Формат файла, создаваемого `exportforgrades` и читаемого `loadgrades`, —
текстовый, построчный, с явными метками полей. Пример:

```text
#GROUP:ИУ-701
ID:1001
ФИО:Иванов Иван Иванович
Оценка:5
ID:1002
ФИО:Петров Петр Петрович
Оценка:
```

Правила разбора при загрузке:

- Строка `#GROUP:<имя>` — заголовок группы (служебный).
- Строка `ID:<число>` — запоминает текущий ID для последующих полей.
- Строка `ФИО:<имя>` — информационная, на загрузку не влияет.
- Строка `Оценка:<число>` — если после метки есть цифра, оценка проставляется
  текущему студенту на указанную в команде дату; пустое значение `Оценка:`
  означает «не заполнено» и пропускается.
- Строки, не соответствующие меткам, и значения без цифры игнорируются.

## 7. Обработка ошибок и валидация

- Единый маркер некорректной команды — вывод `INVALID COMMAND`.
- Деструктивная операция `clear` требует явного подтверждения (`y`/`n`);
  без подтверждения база не изменяется.
- `addstudent` отклоняет дубликат (то же ФИО в той же группе).
- `addgrade` не перезаписывает существующую на дату оценку, а направляет
  в `changegrade`.
- `riskstudents` принимает порог строго в диапазоне (0, 5].
- `loadgrades` устойчив к частичной некорректности файла: проблемные строки
  пропускаются, валидные — применяются.
- Ошибки ввода/вывода файлов (нет доступа, битый формат) приводят к отказу
  команды без повреждения состояния базы.

## 8. Сборка и запуск

Требуется компилятор с поддержкой C++17 (GCC 7+, Clang 5+, MSVC 2017+).

### 8.1 Через CMake (рекомендуется)

Положите заголовочные файлы в `include/`, исходники — в `src/`. Пример
`CMakeLists.txt` в корне проекта:

```cmake
cmake_minimum_required(VERSION 3.14)
project(students_db LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

file(GLOB_RECURSE SOURCES CONFIGURE_DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/src/*.cpp)

add_executable(students ${SOURCES})
target_include_directories(students PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/include)
```

Сборка и запуск:

```bash
cmake -S . -B build
cmake --build build
./build/students                 # пустая база
./build/students base.txt        # загрузка из файла
./build/students --help          # справка
./build/students --check base.txt
```

### 8.2 Без CMake (одной командой)

```bash
g++ -std=c++17 -Iinclude src/*.cpp -o students
./students
```

Имена и расположение `.cpp`/`.hpp` приведите в соответствие с фактической
структурой вашего репозитория.
